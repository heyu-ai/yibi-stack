## 1. 產物目錄與併發隔離

- [x] 1.1 交付產物目錄建立腳本：接受 PR 號後於標準輸出印出隔離產物目錄的絕對路徑鍵值行、把 artifact root 註冊進版本控制的 exclude（路徑須向 git 查詢取得而非字串拼接）、註冊具冪等性且不覆寫既有內容、缺參數或缺參數值或 exclude 不可寫皆以明確訊息與非零退出結束且不產生解譯器堆疊、同 PR 重跑與多 worktree 併發不互相覆蓋且陳舊產物被偵測。對應 design「審查產物目錄與併發隔離」與 spec「Review artifacts are isolated per pull request and never silently reused」。驗證：`plugins/growth/skills/pr-retro-hard/scripts/tests/test_setup_retro_review_dir.py` 涵蓋逐行精確附加、連跑兩次不重複、連結式 worktree 下路徑正確、既有內容保留、不可寫時明確失敗、缺參數與缺值分別失敗六案，且每案先以已知壞輸入證明會紅。

## 2. 彙整核心

- [x] 2.1 交付 finding 資料契約：以 JSON schema 定義 target、分類、settling check 描述子與 statement 四欄，分類為封閉列舉且無 catch-all 成員，settling check 解析為五值列舉，未知分類或缺 target 或缺 statement 一律明確錯誤且不套用預設值。對應 spec「Finding structure uses closed enumerations and malformed input fails loud」與「Settling check carries five distinct execution states」。驗證：`test_aggregate_review.py` 對三種壞輸入各斷言明確錯誤與錯誤訊息含違規 finding 識別，並斷言「無法執行」不被折疊成「反證」。
- [x] 2.2 交付評分單向性：彙整對同一輸入增加任意數量的附和 finding 後，confidence 與 source 值均不變；只有異議能降低 confidence；source 為使用者陳述者不被降格覆寫而是另行記錄異議。對應 design「彙整規則抽成可執行核心並作為唯一決策所有者」與 spec「Agreement never raises confidence and never rewrites the source label」。驗證：`test_aggregate_review.py` 以 spec 內單向性表格的五列為參數化案例，並含「三 voice 全附和」的正向對照斷言輸出等於輸入。
- [x] 2.3 交付呈現不變量：對抗 voice 的 finding 不計入任何共識計數且與外部 voice 分開回報，缺 settling check 的對抗 finding 降為非作用性註解（仍呈現但不影響評分、tier 與草稿），缺 settling check 的外部 finding 上限為未決；所有草稿項目逐字保留、只加註不刪改。對應 spec「Adversarial findings never count toward consensus and a missing settling check is non-actionable」與「Draft items are annotated and never removed by aggregation」。驗證：`test_aggregate_review.py` 斷言無 settling check 的異議不產生任何處置、且兩個 voice 對同一草稿項目異議時該項目原文仍在輸出中。
- [x] 2.4 交付 tier 降級為建議且以已執行證據為前提：斷言「證據不支持」類 finding 僅在其 settling check 狀態為 confirmed 時才產出降級建議，且該輸出標記為既有 evidence gate 的輸入而非已套用的決定，彙整不直接寫入任何 lesson 儲存。對應 design「tier 降級以已執行證據為前提」與 spec「Tier demotion is a recommendation gated on a confirmed settling check」。驗證：`test_aggregate_review.py` 對 settling check 五狀態各跑一次，僅 confirmed 那列產出建議。
- [x] 2.5 交付輸入衛生不變量：彙整取草稿與審查包的 digest 為輸入，餵入 digest 不符的舊 finding 時標記為陳舊或拒絕且不套用；同一 finding 集合以不同 voice 順序供入時輸出相同；重跑同一集合輸出相同且不重複計票、不重複套用 confidence 變更。對應 spec「A semantic change to the draft invalidates prior findings」與「Aggregation is order-independent and idempotent」。驗證：`test_aggregate_review.py` 含 permutation 與 idempotence 兩個性質測試，以及「草稿被校準後餵入舊 finding」的陳舊案例。
- [x] 2.6 交付 shadow 旗標與契約雙向一致性：降級建議一律計算並回報，是否據此行動由預設關閉的顯式旗標控制，旗標關閉時 tier 不變；彙整另提供 policy 說明輸出，機械檢查雙向斷言實作能產生的每個 outcome 都有 runbook 說明、runbook 提到的每個 outcome 都存在於實作。對應 design「Shadow 出貨：降級建議預設不生效」與 spec「Demotion recommendations are inert until explicitly enabled」與「Aggregation core is the single decision owner and its runbook summary is cross-checked」。驗證：`test_skill_contract.py` 以「從 SKILL.md 摘要表刪掉一個 outcome 說明」作為正向對照斷言交叉檢查會紅，並反向斷言 runbook 虛構 outcome 亦會紅。

## 3. 審查輪 runbook

- [x] 3.1 交付兩個插入點的邊界：runbook 明訂第一輪在引擎推論出五題草稿後、交付人類校準前執行，第二輪在引擎完成分級後、寫檔建議產生前執行且審查標的僅為建議文字而非人類已批准的最終修補，且不改變寫檔權限歸屬；其餘步驟明寫照 `plugins/growth/skills/pr-retrospective/SKILL.md` 原樣執行並點名其為所有者，本檔不重新推導其任何 gate；草稿無可重用教訓時第二輪跳過且不報為失敗。對應 design「委派 pr-retrospective 為流程引擎而非複製其 runbook」與「M2 審查的是建議文字，不改變寫檔權限」與 spec「Review rounds are bounded to two insertion points owned by the retrospective engine」。驗證：`test_skill_contract.py` 斷言必要段落與委派句存在，並人工複閱兩個插入點的敘述與引擎步驟編號一致。
- [x] 3.2 交付 voice 取得與退化階梯：runbook 以呼叫既有 `plugins/3rd-tools/skills/codex-consult` 與 `plugins/3rd-tools/skills/agy-consult` 取得外部 voice 並依賴其自有偵測、auth gate 與失敗停止條件，不重寫偵測、不讀 `/pr-cycle-deep` 的偵測快取；審查包以檔案絕對路徑指標傳遞而非內嵌且不使用 at 前綴形式；每 voice 輸出經必要段落、最小長度與代理敘述檢查，失敗重跑一次、連續兩次後標記不可用並警示但不阻擋；零外部 voice 時流程仍完成並宣告單一 voice 使一致無訊號；文件明記哪些 PR 內容會外送與如何在仍執行對抗 voice 的前提下退出外送。對應 design「透過既有 consult skill 呼叫外部模型並以檔案指標傳遞審查包」與 spec「Voice availability is detected by delegation and degradation is explicit」與「Each voice output is validated and repeated failure is bounded」與「External model data boundary is disclosed」。驗證：`test_skill_contract.py` 斷言不含 at 前綴指標形式與偵測快取檔名，並以截斷輸出與 150 位元組輸出兩個壞樣本人工確認驗證段落會判定為失敗。
- [x] 3.3 交付審查包純度：runbook 規定審查包只含引擎實際蒐集到的原文、草稿逐字與開放式問題三類內容，禁止帶結論或預設特定缺陷的是非題；所有 PR 衍生文字置於明確分隔標記內並標為待審資料而非指令。對應 spec「Review packet contains only collected source material and open-ended questions」與「Embedded pull-request text is delimited as untrusted quoted evidence」。驗證：人工複閱 runbook 內的問題範本逐條對照 spec 的引導問句對照表，並確認分隔標記說明存在且 PR 原文不落在指令位置。
- [x] 3.4 交付共識來源限定：runbook 規定首輪所有 voice 互盲、共識僅由首輪 finding 計算、首輪零 finding 的 voice 在交叉輪無共識資格、報告須指名共識由哪幾家建立；交叉輪僅在兩個外部 voice 對同一標的出現相反處置時啟動，且只允許反證、降級、撤回與補 settling check，不得新增獨立票。對應 design「共識僅由獨立首輪建立」與 spec「Consensus is established only by the independent first round」與「Cross round is conditional and cannot add independent votes」。驗證：`test_skill_contract.py` 斷言交叉輪啟動條件與四種允許動作的敘述存在，並人工複閱「全體反對草稿但彼此不衝突」時記錄跳過與理由。
- [x] 3.5 交付對抗 reviewer 的唯讀約束：runbook 以內建 `general-purpose` subagent 執行對抗審查而不新增自有 agent 定義檔，prompt 內含唯讀約束，派工前後各取一次工作樹狀態並於相異時警示並指名差異，且明記此約束由指示與比對而非工具移除達成的殘餘風險。對應 design「對抗 reviewer 使用內建 general-purpose subagent」與 spec「Adversarial reviewer is constrained to read-only behavior and tree mutation is surfaced」。驗證：`uv run python scripts/lint_skill_scope.py` 通過（證明未派送自有 plugin agent），並人工複閱前後比對步驟與殘餘風險敘述存在。
